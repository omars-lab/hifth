# Licensing map

Hifth's own work is **GPL-3.0-or-later** (`LICENSE`). But the repository also carries
data it did not write, under terms it cannot change, so a single blanket statement would
be inaccurate. This file is the map: which terms cover which paths, and why.

`SOURCES.md` is the authority on every third-party source — its provenance, its verbatim
license text, and where the notice ships. This file only says how those terms compose.

## The three buckets

| Paths | Terms | Whose choice |
|---|---|---|
| `apps/web/`, `packages/core/`, `packages/etl/` (scripts), `scripts/`, `docs/`, config | **GPL-3.0-or-later** | Ours |
| `apps/web/public/assets/roots/**` | **GPL-3.0** (inherited) | The Quranic Arabic Corpus's |
| `apps/web/public/assets/skins/**` | **CC BY 4.0** (inherited) | quran-tajweed's |
| `apps/web/public/assets/adj/**` | Free use with attribution (inherited) | Waqar144's |
| `apps/web/public/assets/pages/**`, `packages/etl/data/**` | Each source's own terms — **not ours to relicense** | KFGQPC, QAC, quran-tajweed |

## Why GPL for our code

Copyleft, chosen so improvements come back. The plain GPL rather than the AGPL, and the
reasoning is specific to what Hifth is: a fully static, backend-free PWA hands the browser
its entire JS bundle, so anyone deploying a modified Hifth is already **conveying** the
code under §4–6 and owes their users the source. The AGPL's §13 exists to close the
network-service hole — the case where the modified code runs on a server the user never
receives — and Hifth has no server to hide behind. Taking the AGPL would add real adoption
friction to cover a case the architecture does not have.

It also collapses a seam. The derived root shards are GPL-covered whatever we do (below),
so licensing our code GPL makes "GPL, except the vendored upstream assets under their own
terms" the whole story, instead of a code license and a data license in tension.

## Why the root shards are GPL, and what that obliges

`apps/web/public/assets/roots/**` is generated by `packages/etl/scripts/build-roots.mjs`
from the Quranic Arabic Corpus morphology. Under a strict reading — the one we design to —
those shards are a derivative work of a GPL-licensed input, so they carry GPL terms
forward. Two consequences we actually have to honor:

1. **Corresponding source must reach recipients.** For the shards that means
   `packages/etl/scripts/build-roots.mjs` plus the pinned input at
   `packages/etl/data/roots/quranic-corpus-morphology-0.4.txt`. Both are in this
   repository — which discharges the obligation **only once the repository is reachable by
   the people receiving the shards.** See the deploy note below.
2. **The notice travels with the data.** `assets/roots/<edition>/NOTICE.txt` is emitted
   beside the shards by the build, quoted verbatim from the source header so it cannot
   drift, and the app shows a visible credit and copyright line on the root lens.

The corpus's terms of use and the GPL contradict each other on modification (GPL §5 grants
it; the terms say changing is not allowed). We satisfy both readings rather than picking
one: the file is vendored **verbatim and never edited**, and the shards are derived from it
at build time. `docs/decisions/loop-5.md` records the full analysis.

The app *code* is not a derivative of the corpus data — it reads the shards at runtime —
so nothing here reaches our source by way of the data. Our code is GPL because we chose
it, not because the corpus required it.

## The deploy trigger

**Publishing the site is distribution.** A static app hands the browser real copies of
`assets/roots/**`; that is conveying under the GPL, not merely operating a service, and
§13's network provision does not cover it. So from the first public deploy onward the
corresponding source has to be reachable by anyone who loads the page.

Practically: **do not publish the site while this repository is private.** Either open the
repository, or publish the ETL script and its pinned input alongside the deployment. Today
the repository is private and nothing is published, so no obligation has triggered.

## What we do not license

The mushaf page artwork (`assets/pages/**`) is KFGQPC's, distributed under the Complex's
own terms, and is reproduced here unmodified. Nothing in `LICENSE` grants rights to it.
The same holds for every vendored input under `packages/etl/data/`. When in doubt, the
per-source entry in `SOURCES.md` governs — not this file, and not `LICENSE`.
