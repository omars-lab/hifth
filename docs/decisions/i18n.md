# The chrome's language layer moved to a message compiler

**Status:** shipped.
**Date:** 2026-07-30.
**Design:** [`docs/design/i18n.md`](../design/i18n.md) — the forward-looking document.
Read that one before touching the language layer. This is the short record of what was
actually decided, measured, and proven, and it does not repeat it.

## The decision

Replace the hand-written `Strings` table in `apps/web/src/i18n.tsx` with **ICU
MessageFormat catalogs compiled to TypeScript at build time**.

- Catalogs: `apps/web/src/messages/<locale>.json`, flat key → ICU source.
- Compiler: `scripts/messages-compile.mjs` + `scripts/build-messages.mjs`
  (`pnpm i18n:build`), using **`@messageformat/parser`** — a **devDependency**, zero bytes
  shipped.
- Runtime: `apps/web/src/messages/plural.ts`, twelve lines over the browser's own
  **`Intl.PluralRules`**. No vendored CLDR: this app is offline-first and a build may run
  for years without an update, so plural data the *platform* refreshes beats plural data we
  froze.
- Generated TypeScript is **committed** (`*.gen.ts`), so `tsc` is the completeness lock and
  code review sees the output.
- One assembler, `buildStrings(lang, catalog)`, produces the existing `Strings` shape for
  every locale. `useT()` and all ~130 call sites are unchanged.

**Rejected**, with the measured cost of the machinery for one Arabic six-category plural
(bundled with the app's own Vite, esbuild-minified, gzipped, over a hand-written ternary
floor of 151 B):

| candidate | gz | over the floor |
|---|---:|---:|
| **compiled + `Intl.PluralRules` — chosen** | **331 B** | **+180 B** |
| compiled + `@messageformat/runtime` | 386 B | +235 B |
| `@lingui/core` | 9,282 B | +9,131 B |
| `intl-messageformat` (FormatJS) | 14,164 B | +14,013 B |
| `@messageformat/core` in the browser | 25,217 B | +25,066 B |

`@messageformat/runtime` lost on staleness, not size. `@lingui/core` lost because its
completeness story is a *runtime* fallback to the source string — the exact failure this
design exists to prevent. Design §③ has the reasoning.

## What it bought

**A real plural, arithmetically.** Arabic has six CLDR categories and `few` is
`n % 100 = 3..10`, not `n <= 10`. The table this replaced used `n <= 10`, so a distance of
103 pages read «١٠٣ صفحة» where Arabic wants «١٠٣ صفحات» — wrong for **41 of the 603
distances** the mus'haf can produce (103–110, 203–210, … 603). It compiled, it passed, and
nobody would have filed it. `AR.distance(103)` is now pinned in `i18n.test.tsx`.

This is the **one intentional behaviour change** in the migration. It is unreachable in the
current three-page build (the largest distance is 12), so no aria snapshot moves.

**A locale that cannot be half-declared.** `Lang` is derived from the catalogs that exist;
`LOCALES` is `Record<Lang, Locale>`, so a new `messages/ur.json` fails to compile until
Urdu has declared a direction, a self-name, a surah-name table, its digits and its
rule-name order. None of those has a defensible default — a locale silently inheriting
`ltr` is a mus'haf rendered backwards.

## Measured

`gate:budget` caps total shipped gzipped JS at 150 KB.

| | total gz | app chunk | headroom |
|---|---:|---:|---:|
| before (hand-written table) | 101.2 KB | 90.4 KB | 48.8 KB |
| after | **103.0 KB** | 92.2 KB | **47.0 KB** |

**+1.8 KB gz.** Only 180 bytes of that is machinery; the rest is that a key is now written
three times (once per locale's `.gen.ts`, once in the assembler) where it was written twice.
That third mention is what buys the single assembler, and it does not grow with the next
language: a fourth locale costs its own words and nothing else.

## How completeness is enforced now

Three locks. Design §④ has the full statement; the property is *a key present in `ar` and
missing in `en` must never render English inside an Arabic sheet*.

1. **`tsc`.** Each locale's compiled module is `const messages: Catalog`. A missing key, an
   extra key, or a message using an argument no locale declares is a build error. Stricter
   than the `Strings` interface it replaces, which could only see arity. **There is no
   runtime lookup and no fallback chain** — a missing key is not a runtime condition.
2. **`gate:i18n`** (`scripts/gate-i18n.mjs`) — registered in all three places:
   `package.json` `gates`, the `Makefile` `ci` target, `.github/workflows/ci.yml`. It
   closes the four holes `tsc` cannot see: stale generated code, key-set drift against the
   reference locale, an incomplete (or dead-cased) plural checked against
   `Intl.PluralRules(locale)`, and a dropped placeholder or disagreeing `select`.
3. **`i18n.test.tsx`** walks `LOCALE_IDS`, so a locale added tomorrow is under test the day
   its catalog lands.

## Proven by inducing the failure

Not asserted — run, watched, reverted. Verbatim output:

**A key removed from `en.json`** (`"close": "Close"`):

```
$ pnpm gate:i18n
  apps/web/src/messages/en.gen.ts is stale — run `pnpm i18n:build` and commit the result
  en.json — missing key 'close' (it is in ar.json)
gate:i18n — FAIL: 2 problem(s)

$ pnpm i18n:build && pnpm typecheck     # regenerate, so only tsc is left
apps/web typecheck: src/messages/en.gen.ts(12,7): error TS2741: Property 'close' is
missing in type '{ about: () => string; … }' but required in type 'Catalog'.
```

**Arabic's plural reduced to two categories** (`zero`/`one`/`two`/`few` deleted from
`distancePages`):

```
$ pnpm gate:i18n
  ar.json — distancePages:n handles [many, other] but ar has [few, many, one, two, zero,
  other]; missing few, one, two, zero. An unhandled category falls to 'other', which is
  how «١٠٣ صفحة» happened.
gate:i18n — FAIL: 1 problem(s)
```

**A placeholder dropped in translation** (`"Hopped to {label} · page {page}"` →
`"Hopped to a similar verse"`):

```
$ pnpm gate:i18n
  en.json — 'hoppedTo' never uses {label}, which ar.json does. A dropped placeholder is a
  sentence missing the thing it is about.
  en.json — 'hoppedTo' never uses {page}, which ar.json does. A dropped placeholder is a
  sentence missing the thing it is about.
gate:i18n — FAIL: 2 problem(s)
```

All three reverted; `gate:i18n — OK (2 locales × 147 messages, generated code in step)`.

## What did not change, on purpose

- **`useT()`'s shape.** Still `{ lang, dir, t, setLang, other }`. Not one call site moved.
  Two workstreams are live on this branch line and the merge had to stay survivable.
- **Every Arabic and English word.** Transcribed byte-for-byte, including two existing
  inconsistencies kept deliberately so the diff stays reviewable: `stageFailed` uses
  Arabic-Indic digits where `pageN` uses Latin, and `hopSheetAria` / `rangeAria`
  interpolate raw Latin numbers into Arabic aria-labels. Both are now one JSON edit, and
  both want a hafiz's eye and their own commit. Design §⑨.
- **The aria snapshots** in `apps/web/e2e/__aria__`. None regenerated; none needed to be.
- **The licence credits.** `CREDITS` in `components/Colophon.tsx` stayed exactly where it
  was; `gate:license-copy` still binds every row byte-for-byte to `SOURCES.md`. Attribution
  is a legal string, not copy.
- **Page numbers are Latin digits in both languages.** «صفحة 7», not «صفحة ٧» — pinned by
  `i18n.test.tsx` for every locale, not just for Arabic.
- **No third locale.** The deliverable was the framework and the proof it scales; a stub
  translation looks like proof and is a hole. Design §⑦ is the checklist for a real one.

## The superseded argument

The old module doc's case against a library is not deleted — it is quoted at the top of
`i18n.tsx` and answered there and in design §①. Its conclusion followed from *exactly two
languages*, and the bundle clause it rested on is the reason this design puts the library
in the **build** rather than in the bundle. The one thing it got exactly right, and which
this keeps: completeness must be a build-time guarantee, never a runtime fallback.
