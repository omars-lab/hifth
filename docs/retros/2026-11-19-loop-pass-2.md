# Loop pass 2: a rough build of larger text

**What was done.** The three ways for larger text (follow the phone everywhere, only in the
panels, a size of our own) were built roughly, picked by a link and kept on the device. They
live in a separate build (`make text-grow-serve`, `make text-grow-e2e`), because the app had
0.3 KB of room under its 220 KB size limit and the switch costs 0.6 KB.

**What the build taught that no list had.**
- Past 1.25 times, the top bar does not fit an iPhone SE (375 px): it pushes the screen 53 to
  68 px sideways and cuts off the page. So the top bar stops at 1.25.
- The phone's default bottom bar is the "case" kind, which has no toolbar role, so a style aimed
  at toolbars missed it. The bars needed their own marks.
- Loading the switch later made the size worse, not better: the limit counts every file, and a
  later-loaded file brings its own wrapping.
- A shorter rewrite of the code saved nothing; the minifier had already done that.

**Faults found and fixed.** The size warning read the limit from the main folder (210 KB), not
from the branch the check ran on (220 KB), so it called a passing check 9.7 KB over. It now
reads the limit the check printed. Test first.

**Left for the next pass.**
- Look at each way on the SE simulator at its largest size, in Arabic too; then open the
  decision through the `decide` skill.
- The `panels` and `phone` ways were not checked by a browser test: the test browser has no
  phone text size. They are owed a look on the simulator.
- No session note was folded this pass; the oldest unfolded one is next.

**For a skill.** `optimizing-performance`: say in the trims list that loading a small file
later raises the counted total, so it is no way around the limit. `testing`: when a test passes
on first write, check which build `dist/` holds before believing it; this pass's "no switch"
