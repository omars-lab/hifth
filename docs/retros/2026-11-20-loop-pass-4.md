# Loop pass 4: the two larger-text faults the iPhone showed

**What was done.** Both faults from the last pass were fixed in the rough build of larger text,
each with a browser test that went red first (`apps/web/e2e/text-grow.spec.ts`):

- On an iPhone SE at 1.25 times, the grown top bar now hides the tagline and the mus'haf name, so
  the info button stays on the screen.
- The verse drawer no longer covers the chosen verse at 1.5 times. With no tool open, it sits in
  the bottom bar's room, which the page already keeps clear, so it never told the page where its
  top was. Grown, it stood 68 px taller than that room. In the larger-text build it now always
  tells the page its top, and counts its own growth.

The oldest session note (the Nov 13 feature check) was folded into `walk-app`.

**What went wrong, and what to keep.**

- A larger-text build was made in the same working copy while a push's tests were running there.
  It replaced the built app under the push's feet and took its port, and two iPad tests needed a
  second try. Never build in a working copy while its push is testing.
- The first top-bar test passed in Arabic and missed the fault: the test browsers start in
  Arabic, and English is the wider row. A layout test on a small phone runs in both languages.
- In code, a part grown with CSS `zoom` reports its height before growing (`offsetHeight`), while
  its box on screen (`getBoundingClientRect`) is the grown one. Multiplying by the growth was not
  enough here; the real cause was that the drawer never reported at all. Print the numbers
  before guessing at a second cause.

**For a skill.** `testing`: do not build in a working copy while its push runs; layout tests on a
small phone run in English as well as Arabic. `walk-app`: walk follow-the-phone at 2 times on the
SE simulator, where the drawer covered the whole page before this fix.
