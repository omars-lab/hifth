A pure navigation instrument for huffaz. Four bands: sources feed an offline ETL that emits static data, consumed by a three-layer runtime with no backend. The rule that holds it together: assets are never modified, and only one component — the Highlighter — is allowed to know what an SVG is.

٢ETL pipeline five passes; two gates; deterministic output
① Anchor extraction

Read each asset’s own metadata (polygon JSON, markers, md-word IDs, QUL layout DB) → resolver tables:

anchor_ayah(edition, s:a → page, element_id, bbox, marker) anchor_word(edition, s:a, w → page, element_id, bbox) concordance(edition_a ⇄ edition_b)
② Edge normalisation

Every source speaks a different addressing scheme (absolute ayah numbers, s:a pairs, phrase IDs). All are rewritten to canonical keys (quran/hafs-kfqc/2:48#w6-14), deduped, weighted, tagged with provenance.

③ Direction annotation

For each edge, precompute Δsurah, Δpage, same-juz from the anchor tables. This is what turns a generic “related verses” list into the hafiz-shaped buckets: same surah / earlier / later / nearby.

④ Root index build

Morphology → root → occurrences shards with lemma sub-grouping and page numbers, pre-sorted so the runtime can rank by page distance for the current reader.

⑤ Tajweed skin maps

Rule spans over text positions → mapped through anchor_word → element-ID → rule-class JSON per page. The “colour mushaf” is a stylesheet, not a second asset set.

Gates ⛨

Resolution gate: build fails if any edge endpoint doesn’t resolve in anchors, or any SVG polygon ID is missing from tables. License gate: every source carries its license note or the build refuses it.

٥How links are found every edge type has a derivation method and a provenance trail
↷ Mutashabihsimilar wording Exact / near-exact phrase repetition. Word-range matches from QUL phrase data give the precise shared span; the hifz-curated set filters to pairs that genuinely confuse memorisers and adds the ctx (continuation) flag. Rendered as a token diff: شَفَاعَةٌ ↔ عَدْلٌ swap made visible. QUL phrases · Waqar144
≈ Related meaningsecondary weight Scholar-derived relatedness. Pairs extracted from classical tafsir cross-references (Ibn Kathir) with graded strength — trusted because a scholar linked them, not an algorithm. Always visually subordinate to wording matches. QurSim (LREC 2012)
⬡ Shared rootmorphology Same triliteral root, computed from morphology. Lemma-identical matches rank above root-only; occurrences sort by page distance from the reader — “this root recurs on the facing page” beats occurrence #214 far away. Quranic Arabic Corpus · QUL morphology
⚭ Hadith citationreserved Curated citation mappings (ayah referenced in a hadith), later enriched from the SemanticHadith knowledge graph. Hop target is a reference card, not a page — the highlighter is never involved. Quran.com API · SemanticHadith
✎ Tafsir cross-refreserved Structured exegesis links from RDF tafsir graphs (verse ↔ commentary ↔ embedded citations), filtered to navigational value only. SemanticTafsir (al-Ṭabarī)
∿ Embedding similarityreserved · always secondary ML-suggested edges (transformer relatedness over QurSim-style training data) — kept visually distinct from scholar-curated links, never mixed into mutashabih buckets. A suggestion tier, not an authority tier. AraBERT-class models (optional)
