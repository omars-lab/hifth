Hifth app links

Version 1.0.0 · rendered from docs/design/app-url-scheme.openapi.json by scripts/build-app-url-scheme.mjs. The same contract in Swagger UI, or as raw JSON. Every example below is run through the app's own parser by its tests, so the table says what the app does, not what it was meant to do.

The app is not a web server. These are hifth:// links the operating system hands to the installed app: from a tapped link, from Shortcuts, from a script (open, xcrun simctl openurl). OpenAPI is used here as a way to write the contract down in one place that both people and tests read: native/HifthTests/XCallbackTests.swift runs every example under x-examples through the real parser, and docs/design/app-url-scheme.html is rendered from this file by scripts/build-app-url-scheme.mjs.

Two kinds of address. A plain link (hifth:///hafs-kfqc/2:255) turns the page and says nothing back; a bad one is ignored. An x-callback-url request (hifth://x-callback-url/open?route=…&x-success=…) does one action and then opens the caller's own address with the result, following the x-callback-url convention (x-callback-url.com): x-success, x-error and x-cancel name where to answer, and an error answer carries errorCode and errorMessage.

The route grammar is the web app's own hash, unchanged: /<edition>/<target>[?query]. The app only checks its shape; the web app decides what it means (docs/query-params.md lists the query keys).

Plain link: open the app at a verse, a page or a run of verses

hifth://{edition}/{target}

The same string as the public site's #/… link, after hifth://. Three spellings are accepted because people paste all three: hifth:///hafs-kfqc/2:255, hifth://hafs-kfqc/2:255, and hifth://open/#/hafs-kfqc/2:255 (a site link's tail). If the app is not running it launches there; if it is, it turns the page. Nothing is sent back, and a link that is not a route is ignored. Use /x-callback-url/open when you need to know it worked. The edition must be one the app ships; the others in the Edition list are refused the same way.

Parameters

edition requiredpathhafs-kfqc, warsh-libya, qalun-libya, hafs-indopak

Which mus'haf, by its id. Only a shipped one opens; the list is Edition below.

target requiredpathstring, matching ^(p[1-9][0-9]*|[1-9][0-9]*:[1-9][0-9]*(-([1-9][0-9]*:)?[1-9][0-9]*)?)$

A page (p45), a verse (2:255), a run of verses (2:47-2:48 or 2:47-48). Every number starts from 1.

queryquerystring, matching ^[A-Za-z0-9\-_.~%:,=&+]*$

Any of the web app's own keys, e.g. w=3-7 (some words of the verse), skin=tajweed, field=dark. The full list and what a bad value does is docs/query-params.md.

Open the app at a route, then tell the caller

hifth://x-callback-url/open

Turns the page to the place named and, once the page is showing it, opens x-success with the route and the same place's public url added. Name the place plainly: page=45; verse=2:255 (a run: verse=2:47-48) with words=3-7 to pulse some of its words; or surah=36 for a surah's context (its first verse, introduction first). edition defaults to hafs-kfqc. Say how to open it: mode=note (or tool=note) for the tool in hand, open=commentary for the verse's commentary or open=context for the commentary led by the surah's introduction, view=one or view=two for the layout. These three names are checked against the app's lists and a misspelt one is refused, so a caller learns about a typo instead of a page that quietly opened without it. Any other key the web app's links understand (skin, field, via, trail; see docs/query-params.md) is passed through as given, so page=7&field=dark opens page 7 on the night desk. route is the same thing as one string, for a caller that already holds a link; when both are given, route wins. If nothing names a place, or the place is not in the grammar, x-error is opened at once. If the page never shows it (a verse that does not exist, for instance), x-error is opened after about eight seconds with route-not-shown. With neither address given the page still turns, quietly.

Parameters

keywherevalueswhat it does
pagequeryinteger

A page of the mus'haf, from 1. Give a page or a verse, not both.

versequerystring, matching ^[1-9][0-9]*:[1-9][0-9]*(-([1-9][0-9]*:)?[1-9][0-9]*)?$

One verse as surah:ayah, or a run within one surah as 2:47-48 or 2:47-2:48. The verse is selected on its page; a run is highlighted.

A surah's context: opens its first verse with the commentary sheet led by the surah's introduction, as verse=N:1&open=context would. 1 to 114. Give one of page, verse or surah.

wordsquerystring, matching ^[1-9][0-9]*(-[1-9][0-9]*)?$

Which words of the verse to pulse: 3-7, or 5 for one word. Needs verse.

editionqueryhafs-kfqc, warsh-libya, qalun-libya, hafs-indopak

Which mus'haf, by its id. Defaults to hafs-kfqc, the only one shipped today. A name not in the Edition list, or one not shipped yet, is refused with bad-route and a message naming the shipped ids.

routequerystring, matching ^/[a-z0-9-]+/(p[1-9][0-9]*|[1-9][0-9]*:[1-9][0-9]*(-([1-9][0-9]*:)?[1-9][0-9]*)?)(\?[A-Za-z0-9\-_.~%:,=&+]*)?$

The place as one string in the web app's link grammar, /<edition>/<target>[?query], for a caller that already holds a link. Percent-encode it, or a & inside its query is read as the end of this parameter. Wins over page/verse when both are given.

modequeryread, select, highlight, bookmark, note, harakat, word, mistake, crop
e.g. note

The mode the app opens in: the page tool put in hand on arrival, named by the word on its button. The same thing as tool; give one or the other. A name not in the list is refused with bad-route.

toolqueryread, select, highlight, bookmark, note, harakat, word, mistake, crop

The web app's own name for mode. Passed through as tool= in the route.

openqueryjump, about, record, shelf, key, editions, tips, lookalikes, roots, commentary, context
e.g. commentary

A panel open on arrival. commentary opens the named verse's commentary (tafsir); context opens it led by the surah's introduction. Both need a verse, and exist only in a build that holds commentary (the private pitch build) — the public app opens the verse and drops the panel. The rest are the app's own panels: go-to, about, the revision record, the record at juz scope, the tajweed colour key, the mus'haf picker, the tips strip, a verse's look-alikes, a verse's roots. A name not in the list is refused with bad-route.

viewqueryone, two
e.g. two

One page or two side by side on arrival, on a screen wide enough for two. A phone always shows one.

skinquerytajweed

tajweed turns the tajweed colours on. One of the web app's own keys, passed through; the others in docs/query-params.md pass the same way.

fieldquerystring

The desk colour the mus'haf lies on, e.g. dark or tan. Passed through; an unknown value falls back to the default desk.

x-successquerystring, uri

Where to answer when the action worked. Any app's address (shortcuts://…, drafts://…, https://…). The answer's parameters are added to its query. Ignored if it points back into this app, or at a file or a script.

x-errorquerystring, uri

Where to answer when the action failed. Opened with errorCode and errorMessage added, as the x-callback-url convention names them. Same safety rule as x-success.

x-cancelquerystring, uri

Accepted for completeness and never opened: neither action here can be cancelled by the reader.

x-sourcequerystring

The calling app's name, per the convention. Accepted and not used; the app shows no 'back to' button.

Ask what the app is showing

hifth://x-callback-url/current

Opens x-success with the route on screen and its public url. If nothing is on screen yet (the app was just launched by this request), the answer waits for the first page to show. There is no error case beyond a missing x-success, which means no answer.

Error codes

An x-error answer carries errorCode, one of missing-route, bad-route, unknown-action, route-not-shown, and a plain errorMessage.

missing-route: open named no page, verse, surah or route. bad-route: the place is not in the grammar (a page of 0, two places at once, words without a verse, a surah past 114), or a mode, panel or view name not in the app's lists, or an edition not in the list or not shipped yet. unknown-action: the path after x-callback-url is not open or current. route-not-shown: the place was accepted but the page never showed it.
