Which words does the app line look-alikes up on?

When two verses open the same way, the app washes the phrase they share so the eye is taught the seam. To wash it, the app must know that phrase word for word — and it can count those words two ways. This page draws what the choice between them keeps and drops, on the real pages where they differ.

Status Open · asked 2026-09-03

This is the picture the decision record points at. Every run below is drawn on the printed page it actually sits on, washed exactly as the look-alike panel washes it. Rebuilt from committed findings — no scripture travels in this page.

Words this page usesThe three words to have first

look-alikes
Two verses that begin with the same phrase and then diverge — the pairs a hafiz most often slips between. Known in the tradition as mutashabihat.
shared run
The stretch of words a look-alike pair has in common, taken as the longest run they share and kept only where it sits in exactly one place on each side.
the page's words vs. the corpus's
The printed mus'haf has its own words; a separate word-by-word reference we carry has its own count of the same verse. The two mostly agree, but the printed page splits some short joining particles the reference writes joined — so a phrase is often more words on the page, never fewer.

The questionWhat is being decided?

The shared runs are worked out once when the app is built. The question here is only which set of words they are counted in: the printed page's own words, or the separate word-by-word reference we carry today. Nothing else about the look-alike panel changes — only which words of an agreed pair get washed.

It is asked now because the reference we count in today comes under a share-alike licence that reaches whatever the app builds from it, and the printed page's words — already carried, already read — do not. Counting the runs in the page's own words would take the whole look-alike feature out from under that licence and delete a conversion step besides. The catch is that it does not keep the same runs.

The churn is the split itself. Because a phrase is never fewer page-words, some runs grow long enough to become the single place they occur — a new run appears — while a short joining particle that repeats across the page forges a fresh tie elsewhere and dissolves a run that used to be unique. So the trade is bounded, and it is a trade: 114 runs a reader can land on today disappear, 150 new ones appear, and the feature stops being a share-alike derivative.

What already decides part of thisWhat constrains it?

  • What the app is allowed to give away, by channel. The look-alike tree is computed into something the app ships, not merely read to check it, so the licence under the reference reaches the reader. On the web served today that costs nothing anyone must act on; in a channel where a store forbids share-alike terms it would, and that is the case this option is insurance against.
  • What the look-alike panel draws. It washes its colours off exactly these runs. That decision took the runs as given and correct and did not reopen them — this is where they are reopened, so the two must be read together. If the page's words win, 114 pairs lose the run they land on and 150 gain one.

Prior artWhat do others do about this?

I did not look outside the project for this one, and should say so plainly. The choice is internal: which of two things we already hold to count a run in, both vendored here with their licences known. The public Qur'an-data libraries publish look-alike lists and word-by-word references as separate resources and leave the joining to whoever uses them — which is why this project had to compute the runs itself in the first place. There is no upstream that has made this particular choice for us to follow.

The optionsSo which words?

#OptionWhat it gets, what it costs
AKeep counting in the reference's words The 2,544 runs that ship today, the conversion step, and the share-alike thread that comes with the reference. Zero work. Doing nothing is A.
BCount in the printed page's own words 2,580 runs, no conversion step, no share-alike thread. Costs 114 runs a reader can land on today to gain 150 new ones.

What else was weighedWhat is not on the list, and why?

  • Keep the reference, fall back to the page only where they disagree. Keeps the share-alike thread — shedding which is the whole gain — so it buys the churn without the payoff. Out.
  • Count in the reference but ship the runs already converted, to drop the conversion step. Removes the step but not the licence thread, the larger half of the cost. A tidy-up of A, not a third answer.

SensitivityWhat would change the answer?

  • A channel being chosen where share-alike terms bite — a store build. Then B's licence gain stops being insurance and becomes the reason.
  • A hafiz judging the 114 lost runs. If the runs the page drops are ones a reader leans on, the cost is higher than a count says; if marginal, lower. Nobody has looked at which 114 they are, only at how many.
  • The reference being re-licensed permissively. Then the licence half dissolves and only the 114-for-150 churn is left, which on its own does not obviously favour either side.

ScopeWhat is this not settling?

  • The licence question itself — whether the reference binds what we ship, and in which channels — is asked elsewhere and only pointed at here.
  • Which verses are look-alikes. Untouched; only which words of an agreed pair get washed.
  • The four verses whose two printings cannot be lined up at all. They take no part in this and their alignment is not reopened.
  • What the panel looks like. Nothing here changes that — only, if B wins, which 114-and-150 of its pairs shift the run they draw.
