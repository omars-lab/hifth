The owner (2026-09-19) sharpened a tenet: don't try to generate all the pros and cons of a choice
upfront. Build a rough POC/demo — it discovers nuances and considerations that no upfront analysis
would have listed. The clarification, in their words: "pocs will discover more nuances that might
not be considered … not per se reading … but generating all the pros/cons upfront."

**Why:** a pros-and-cons list made before anything exists can only hold what you already thought
of; the things that actually decide a feature (a panel that covers the verse, a reach across the
gutter that feels wrong, a shape you only see is confusing once your hand is on it) are the ones no
list had a row for. Building surfaces them.

**How to apply:** name the options you can already see, then build a quick throwaway POC as the
instrument that finds the rest, and write the pros/cons in full *afterwards* — the ones the demo
taught you, not the ones you guessed. It is NOT "skip thinking" and NOT "don't read". Wording added
to the project CLAUDE.md as a tenet bullet ("A rough build discovers what an upfront list of pros
and cons cannot") beside the felt-difference rule. Relates to [[designs-public-on-site]] and
[[poc-for-study-quran-team]].
