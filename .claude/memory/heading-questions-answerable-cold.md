A question-heading can be jargon-free, be a real question, and STILL be hard to follow when it
is abstract or analogy-shaped. The one that bit us: "Should the code that grades be pinned the
way the data already is?" — no jargon, it is a question, and it is opaque, because the reader
must decode a metaphor ("pinned") and hold a data-vs-code parallel before they can have an
opinion. The plain fix names something concrete that could actually happen: "Could someone
quietly change the checking code without us noticing?"

**Why:** the plain-language tenet already said "no jargon" and "headings are questions," but ①
of the rigor-stack backlog passed all of that and was still philosophical. The gap the wording
didn't name was abstract/analogy framing, a distinct failure from jargon. (Omar, 2026-09-22:
"its not per se jargon but its very philosophical/hard to follow.")

**How to apply:** for any reader-facing heading or option label, run the test — could a stranger
answer it cold, without first unpacking an analogy or metaphor? If not, rewrite it around a
concrete thing that could happen. Codified in project CLAUDE.md under "Headings are questions."
